# Changelog 2026-08-26（RAG 分库 scoop）

## 新功能

### RAG-Service 分库（scoop）机制（v2，两侧同步升级）
- **分库白名单**：RAG-Service 向量按功能块物理隔离存储，scop 白名单 `knowledge` / `memory` / `groupmgr` / `plugin`（服务端枚举硬编码，非法值 400；拼写错误立即暴露而非静默开空库）
- **检索限定分库**：对话前知识召回只搜 `knowledge` 分库、记忆召回只搜 `memory` 分库、群管理核实只搜 `groupmgr` 分库——不同集合的向量不再互相挤占 top-k，**检索精确度显著提升**
- **tag 归属注册表**：同一 tag 跨分库写入/删除返回 409（服务端启动时从各库自动重建），杜绝双删遗漏出死数据
- **独立持久化**：每分库独立 `data/scoops/<name>/index.tvim + tags.bin`，一次写入只持久化 + COW 发布本分库（其余分库快照/磁盘零参与），写延迟随集合规模收窄
- **API 路由升级**：`/tags/{tag}` → `/scoops/{scoop}/tags/{tag}`（batch/search 同理）；`/health`、`/info` 改为 per-scoop 统计

## 变更

- `internal/core/ragtag`：新增 `ScoopKnowledge` / `ScoopMemory` / `ScoopGroupMgr` / `ScoopPlugin` 常量；UUID v5 派生函数不变（tag 值跨版本稳定）
- `infrastructure/rag/handler`：Upsert / BatchUpsert / Delete / Search 全部增加 scoop 参数；`InfoResponse` 结构调整为 `scoops.<name>.{tags,chunks}`
- 知识/记忆候选集职责收敛：从"过滤外来 tag"变为"命中 tag → 本地条目 ID 反查映射"（UUID v5 不可逆，映射表仍必需）；检索 k 收窄：知识 15→10、记忆 20→10、群管理 30→15
- 插件 `jn.rag`：统一写入独立 `plugin` 分库，与业务集合物理隔离
- Web 面板 `RAGPage` 的 Info 展示随响应结构更新（per-scoop 规模）

## 说明

- **部署顺序**：RAG-Service v2 先部署（旧数据目录需清空或按 `data/scoops/<name>/` 布局重建），JuanNiang-Neo 二进制同步升级；旧 v1 路由与数据文件不再读取
- 已有数据丢失风险：**必须**先执行 `DeleteAll`/清空 RAG-Service `data/` 目录再启动（本版本不读旧平铺文件），由知识/记忆手动"同步向量库"按钮重建
- 任何 RAG 故障都不影响主流程：最坏情况回退到接入前行为（记忆 pg_trgm / 知识 SQL 匹配）
